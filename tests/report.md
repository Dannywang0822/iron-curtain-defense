Stub 清单（脚本真正用到的全部宿主 API）：

| 宿主能力 | 做法 |
|---|---|
| `document` | `readyState='complete'`；`getElementById('stage')`→假 canvas、`('boot')`→假元素；`createElement('canvas')`→另一张假 canvas；`documentElement.style.setProperty` no-op |
| canvas 2d ctx | `Proxy`：已知返回值的方法（`measureText`/`createPattern`/`createLinearGradient`）给真形状，**其余任意方法/属性一律 no-op** —— 所以全部绘制代码都真的被执行过 |
| `window` | 自引用；`innerWidth/innerHeight/devicePixelRatio`；`addEventListener` **记录监听器**（A7 键盘测试靠它手动派发 keydown） |
| `localStorage` | 内存 Map（存档健壮性测试靠它注入坏数据） |
| `requestAnimationFrame` | 只入队不回调 → 主循环不自动跑，测试用 `__IV__.tick(ms)` / `T().updateReal(dt)` 手动推时钟 |
| `Math.random` | **替换为确定性 LCG**，保证报告可复现 |
| `AudioContext` | **刻意不提供** → `initAudio()` 立即返回，音频路径成为纯 no-op，`sfx()` 不参与任何断言 |
| `location` | **刻意不提供** → `applyHashEntry()` 立即返回，初始态不受 hash 影响 |

只读导出：IIFE 闭合前注入 `window.__T__ = { G, render, updateReal, endGame, startWave, particles, … }`。
**行为零改动**，仅为拿到闭包内函数（`dmgCalc`/`startWave`/`mapUnlocked` 等本就由作者挂在 `window.__IV__` 上）。

## ⑤ 我判断的风险排序

排序依据：**"多大概率让玩家觉得这游戏坏了 / 不想玩了"**，不是修复成本。

### 1️⃣ M3 的"盲区"实际吞掉了 46% 的地面路径（D-04）— 唯一会改玩法数值的一条

- 实测：盲区 1 段 **736px**（x −180→480），占 1600px 路径的 46%。设计写的是 2 段共 420px。
- 根因是几何必然：M3 的 16 个点位**全部**落在 `x∈[500, 980]`，而地面路径有 660px 压在 `y=592` 的底边上，任何点位射程（最高 212.75px）都够不到（最近点位到该底边 261px）。
- 玩法后果：地面单位的**可击杀窗口从 1180px 缩到 864px（−27%）**。M3 本来就是最难图（55 TP 基准、15 HP），这一下让 W1–W4 的地面波在没有文档支撑的情况下变难；玩家还会看到近一半路面刷着"盲区 · 无火力覆盖"和警示斜纹，容易读成 bug。
- 配套的 D-06（航程 950–993px 而非 900px）是同类问题轻症：M3 的"窗口更短"整体比文档更极端。
- **建议**：要么挪点位让它真的只在两小段盲区（会动点位数量，触及 §11 开放项），要么正式把盲区改写为"1 段 ~736px"并重跑 §4.7 曲线。**这是设计变更，不是工程缺陷，得你和 design-strategist 拍板。**

### 2️⃣ 色板钩子在 24 处漏了（D-01）— 现在唯一的架构门禁缺口

- 验收清单 §0 写明"钩子本期必过"。换色盲档时 `TH.accent` 会变，但 14 处写死的 `rgba(53,224,255,…)` 青色高亮**不会跟着变** —— 次期接三套色板时必然露馅，返工成本比现在高。
- 这些字面量其实都是调色板已有的值（`19,28,38`≈ground、`42,58,76`=grid、`230,240,247`=edge、`255,197,61`=warn、`125,255,178`=ok、`92,107,124`=locked、`10,15,22`=bg），收口成本不高。
- 576 行那个 `'#fff'` 是 `particles[]` 的默认 color，每次 `pSpawn` 都被覆盖、实际不参与渲染，改 `C.white` 即可。

### 3️⃣ 二周目唯一的"差一点"引导缺失（D-02）

- 结算界面会写"本局获得 14 科技点，够点亮【弹道校准】"，但进了科技树，差 4 点的节点只显示 `10 TP` 与锁形，**不告诉你还差多少**。GDD §6.3 明确把"M3 首次尝试 −5 TP"做成刻意的"差一点"，这个引导缺了就白做了。
- 修复成本极低（一行文案），但对"再来一局"的转化率影响不小。

### 4️⃣ 出售少返 1 金币（D-03）

- 3/12 组合（A Lv3、C Lv1、C Lv2）。玩家算得出来："350 投进去怎么只返 244？"
- 修法：`Math.floor(t.invested * MOD.refund)` → 用整数运算（`Math.floor(t.invested * 7 / 10)`）或 `+ 1e-9` 后 floor。⚠ **E1 的 ×0.85 现在 12/12 全对**，改的时候别弄坏——我有专门一条断言盯它。

### 5️⃣ M3 W7 缓冲波越界 0.32%（D-07）/ GDD 两处文档自洽问题（D-05 / D-06）

- 边界擦过，实际手感几乎无感；但既然 GDD 把这几条写成"工程验收线"，就应该留痕。
- **D-05 值得优先处理**：它是 G10.3 断崖检测的分子，而 G10.3 是全套难度曲线里唯一的"预防性"指标。列自身不自洽时，后续任何调平衡都会基于错的断崖判断得出错误结论。
