# 铁幕防线 / IRON VEIL

> 单机网页塔防。在深蓝钢板般的战场上，用四种互相咬合的防御火力，把十二波钢铁洪流按计算逐层剥开 —— 每一局的失败都会变成下一局的装甲。

**单文件交付**：整个游戏就是根目录的 `index.html`，双击即可运行。零外部资源、零网络请求、零构建步骤。

## 快速开始

```
双击 index.html
```

不需要安装依赖，不需要起服务器，不需要联网。断网状态下同样可玩。

## 玩法

三张地图，每张 12 波固定编排。地图按顺序解锁：M1 起始 → 首通 M1 解锁 M2 → 首通 M2 解锁 M3。

| 地图 | 名称 | 点位 | 初始金币 | 特征 |
|---|---|---|---|---|
| M1 | 峡谷关隘 | 14 | 320 | 教学向，路径清晰 |
| M2 | 双流枢纽 | 18 | 300 | 双路分兵 |
| M3 | 穹顶裂隙 | 16 | 380 | 含 2 段射程盲区，击杀窗口最短 |

**四种塔**，每种 3 级，可建造 / 升级 / 出售（返还 `floor(累计投入 × 0.70)`）：

| 键 | 塔 | 底座边数 | 特性 | 对空 |
|---|---|---|---|---|
| `1` | 动能炮 A | 4 | 单体速射 | ✓ |
| `2` | 迫击炮 B | 6 | 溅射 | ✗ |
| `3` | 冷凝塔 C | 8 | 光环减速 | ✓ |
| `4` | 棱镜炮 D | 3 | 穿甲 | ✓ |

> 底座边数是**塔种的第一识别通道**，不是装饰。配合无描边配色，即使完全无法分辨颜色也能靠形状区分四种塔。

**经济**：击杀赏金 + 清波奖励 + 利息（`floor(金币 × 4%)`，上限 40，金币 < 100 不结算）。科技点与实际清波数挂钩，W8 崩盘仍有约 60% 收益 —— 失败不是空转。

**局外成长**：8 节点科技树，F/E/D 三条互不依赖的支线，增益全为线性加法，不做指数滚雪球。

## 可访问性

游戏内设置面板提供：色盲友好色板（红绿色盲 / 蓝黄色盲）、UI 字号放大（1× / 1.25× / 1.5×）、减弱动态效果。

设计上保证：形状（而非仅颜色）编码塔种；正文对比度 ≥ 4.5:1、非文本图形 ≥ 3:1；五类事件反馈均**在被拒对象自身包围盒内**呈现并保留非颜色通道；全键盘可操作且焦点可见。

## 开发过程

这个项目的顺序是 **规格 → 实现 → 验收**，每一步都留下可核查的产物，不是边写边想的。

### 1. 规格先行

先产出 `design/gdd.md`（设计规格书）与 `design/art-bible.md`（视觉规范），两者定稿之后才写第一行代码。GDD 里有一条硬约束：

> 未在本文出现的数值一律视为"未定义"，不得凭空补值。

它的实际效果是：`index.html` 里每个数值都能在 GDD 里找到出处，不存在"实现里悄悄加了个系数"的情况。

### 2. 实现

单文件形态是刻意加的约束，不是为了省事：所有图形由 Canvas 2D 手绘，所有音效由 WebAudio 振荡器实时合成，没有一张图片、没有一个音频文件——所以整个游戏就是约 133 KB 的一个 HTML。

几处改动较大的地方：

- **三套时钟分离**。战斗时间受倍速与暂停影响，HUD / 提示走真实时间，波间倒计时只走**非暂停的现实时间**。最初三者混用，暴露出一个漏洞：玩家可以暂停刷满倒计时，再提前召唤白拿金币奖励。
- **M3 的射程盲区**。按 GDD，M3 应有 2 段路径不落在任何点位射程内，逼玩家在盲区**之前**解决问题。实测初始布局盲区高达 736px 且集中在 1 段，与设计意图不符。挪动 3 个常规点位后降到 384px / 2 段，落在设计声明的约 420px 区间内；点位总数 16 与 12/4 的高低台拆分均未变。
- **出售回收少 1 金币**。`350 × 0.70` 在浮点下是 `244.99999999999997`，直接 `floor` 会少给 1 金币。规则仍是 `floor(累计投入 × 0.70)`，只是先把结果定到分再取整——修正的是浮点表示误差，不是规则。

### 3. 可访问性

不是做完之后补的，与设计同步定义（A1–A7）。其中两条值得单独说：

- **塔种靠形状而非颜色区分**。四种塔的底座边数分别是 4/6/8/3，这是塔种的第一识别通道，配色只是第二通道。
- **反馈必须发生在被拒对象身上**。金币不足、前置未满足这类拒绝反馈，都渲染在被点击对象自身的包围盒内，并保留非颜色通道。用全屏 toast 顶替是不合格的——那样用户得自己回想刚才是哪个按钮被拒了。

为了让"换色盲色板即生效"这条成立，代码里所有颜色都从 `palette.*` / `TH.*` 查表，除色板定义段外不存在硬编码色值。

### 4. 验收

`tests/headless.js` 在无头环境（stub 掉 document / canvas / localStorage / AudioContext）下跑确定性断言，覆盖战斗数值、经济、波次编排、可访问性约束，以及**文档自身的一致性**。输出可复现，不依赖系统时间或外部随机源。

当前状态：**328 项，327 PASS / 1 FAIL**。

那 1 项 FAIL 是刻意保留的：M3 第 7 波相对第 6 波的难度增幅实测 `0.817`，规格下界 `0.82`，偏差 −0.32%。修正它的代价是改动 9 个 GDD 单元格（其中一条金币链没有任何断言覆盖）——为了跨过一条两位小数的线而引入更大的失效风险，不划算。因此登记为已知债，而不是就地改数据。

### 5. 已知遗留

完整清单见 `production/design-handoff.md`，几条主要的：

- M3 修复盲区后可击杀窗口从 864px 增至 1216px（+41%），第 9–12 波的总 HP 大概率需要上调，需试玩后重跑难度曲线。
- 上述增幅下界 `0.82` 精度不足（两位小数卡在舍入边界），应提高精度。
- art-bible §3.1 对塔 B 的孔洞描述欠定，目前只存在于代码实现里。

## 技术说明

- 逻辑分辨率 1280×720，Canvas 2D 手绘，无图片资源
- 音效由 WebAudio 振荡器实时合成，无音频文件
- 三套独立时钟：战斗时间受倍速与暂停影响；HUD / 提示走真实时间；波间倒计时只走**非暂停的现实时间**（倍速不缩放）—— 堵住"暂停刷满倒计时再提前召唤白拿奖励"的漏洞
- 存档写入 `localStorage`
